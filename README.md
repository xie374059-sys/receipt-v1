## 它挡的是什么

七类"假完成",每一类对应一个字段:

| 字段 | 挡的假 |
|---|---|
| `op_id` | 同一件事被投两次,做两遍 |
| `attempts` | 换号重派,幂等门失效（★ **它不在「缺了就拒」那张表里** ——
  因为【缺 attempts 本身不算假】，而【重派时报了号却对不上】才算（规则 3c/7））|
| `status` | 状态机把"收到回执"当成"完成" |
| `evidence_level` | 未验证却标完成 |
| `capability_gap` | 有缺口却标完成 |
| `raw_carry` | 原值被本地化改写 |
| `formal_ack` | 自己宣布"我完成了" |

## 第一张成绩单

`cases/incident-011.json` 用的是 2026-06-28 那天真实的跨机交接失败现场 ——
**状态写着 `completed`,而同一份收据的 `raw_carry` 里 `task_sent_to_codex=false`、`completion_observed=false`,真因是 `lease_status=none` 卡了四小时。**

判定器对那份收据的判决是 **REJECT**,理由一行:

```
raw_says_not_done_but_completed:task_sent_to_codex,codex_exact_reply_observed,completion_observed,lease_status
```

**8/8 全对。** 而这份判据是死的:换谁来跑,都是这一行。

## 怎么用它

1. **接进 CI**:每个 agent 的收据在合并/放行前跑一次,不合法的直接卡住
2. **接进验收**:甲方拿它判乙方交来的收据,不用开会
3. **接进审计**:事后拿它复判历史收据,机械地找出"当时本该被拒"的那些

## 退出码（★ 拿去当闸用的，看这一节）

```
ACCEPT        ⇒ 退出码 0   ★ 只有这一个算通过
REJECT        ⇒ 退出码 1
NEEDS_HUMAN   ⇒ 退出码 1   ★ "判不了"不算通过 —— 那正是它的意思
```

**而 `--json` 的退出码和上面一样** —— 机器读的和你眼睛看的，是同一个判据。

★ 想在 CI 里当闸：

```bash
python3 runner.py 我的收据.json --json || { echo "不合格，别合并"; exit 1; }
```

★★ 要"只要 JSON、不管被拒"的（比如拿它当库用），用 `--不闸`：

```bash
python3 runner.py 我的收据.json --json --不闸   # 永远返回 0，而那是明说的
```

### 这一节是怎么来的

★★★★ **一个陌生人下载去跑，找出来的。**

他跑完 34/34、`py_compile` 也过，然后自己多查了一步，说：

> 「收据被判为 `REJECT` 时，**命令仍然返回 0**；套件运行时也是如此。
>  CI 通常会把退出码 0 当成成功，**因此目前不能只靠退出码阻止不合格收据通过。**」

★ 而我核了：**不加 `--json` 时是对的，加了 `--json` 就一律返回 0。**
真凶是那一行 `return 0` —— 它为了"JSON 输出成功"而写，
而把【"程序跑成功"】和【"收据被接受"】**混成了一件事**。

★★★ 而这条**正好打在这个件最核心的那句话上**：

> 「**一个永远判真的闸，比没有闸更坏。**」

—— 而一个永远返回 0 的闸，就是那个东西。

## ★★★★★ 它判什么、不判什么（**先看这段，不然会误会它**）

```
它判的是   →  你这句话，和你【自己交上来的凭据】，矛不矛盾
它不判     →  这个活【干得对不对】· 答案【对不对】· 该不该这么干
```

### 所以有一件事必须说清：**自洽 ≠ 正确**

**一份收据可以前后完全一致，而它的答案是错的。而它会通过。**

举个具体的：

```
收据说     「我把文件改好了」
凭据写着   「改了 3 个文件，每个都验过」
```

⇒ **这两句对得上 ⇒ 它通过。** ✓

**而如果那 3 个文件本来就不该改 —— 它照样通过。**

★ 因为「该不该改」**不在收据里** —— 那是一个判断，而判断不是比对。

**这是故意的，不是漏洞。** 一个只会比对的东西，好处是**它说的话你能查**；
坏处是**它管不了"比对之外"的事**。而那个坏处**写在明处**。

### 那"活干得对不对"谁来管

```
不在这个件里。它是一件很小的事 —— 只干"收据和凭据对不对得上"。
```

★ 而这个边界**不是藏起来的** —— 这一节就是它。

## 边界(不做的事)

- ❌ 不定义身份 / 凭证 / 传输 —— 交给 MCP / A2A / GB-Z 185
- ❌ 不解释"为什么这么决定" —— 收据不产生理由,只记录事实
- ❌ 不产生正式 ACK —— 永远
- ❌ 不替代可观测性 —— 那个给人看,这个给机器判,而且它**拦人**
- ❌ **不判「答案对不对」** —— 只判自洽不自洽。**一份自洽而答案是错的收据，它会通过。**
  （★ 那是【故意的】—— 见开头那一节。一个只会比对的东西，好处是【它说的话你能查】。）

## 它是从哪来的

**一句话：它是从一次真实事故里长出来的。**

2026-06-28，一次跨机交接：状态机写着 `completed`，而同一份收据的 `raw_carry` 里
写着 `task_sent_to_codex=false`、`completion_observed=false` ——
真因是 `lease_status=none`，卡了四个小时。
**两句话同时在，而没有人把它挑出来。**

那份事故现场现在就在包里：`cases/incident-011.json`（8 条，全部取自当天真实验收证据）。
判定器对它的判决是 **REJECT**，理由一行 —— 而那一行是死的，换谁来跑都一样。

**版本脉络**（★ 都在 git 历史里，随时 `git log` 得出来）：

| 时间 | 是什么 |
|---|---|
| 2026-09-21 | 第一版：一个文件、判一份收据、跑三个手写例子 |
| 2026-10-06 | 这一版：三套用例（34 条）、17 条判定规则、每条规则先有反例再进 runner |

★ **而这一版里有一条规则的出处值得留着**：`R-evid-01`（"有证据"那句话要有东西撑着，
`completed` 而 `raw_carry` 空 ⇒ 转人工）—— 它来自一个**没有先验知识**的执行者。
它把 `raw_carry` 清空 + 自称 `third_party_verified` 推到极端，发现判定是 `ACCEPT`，
而理由写着 `completed_with_evidence_and_no_gap`。
**证据那一格是空的，而结论是满的。**

## 它和那个更大的东西的关系
